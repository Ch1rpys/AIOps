处置链 · 四权分立
判断权、执行权、批准权、判决权，彼此不越界
模型只出判断，程序只执行登记动作，人保留批准权，探针保留最终判决权。
01 · 现场
真实故障
· Docker 隔离环境
· 容器真停 · 接口真 502
· 不是回放日志或动画
禁止：用预录日志代替真实故障
→
02 · 证据
可引用的观测
· 容器状态 + 6 个探针
· 日志 + Runbook + 截图
· 每条证据带 id 与时间
禁止：引用不存在的证据 id
→
03 · 模型
只提议，不动手
· HolmesGPT 诊断根因
· 独立 Planner 报动作编号
· 只能引用目录，不得执行
禁止：直接调用工具或执行命令
04 · 人
计划级批准
· 本机管理员令牌
· 核对 plan_id 与目标
· 批准前真环境零副作用
禁止：复用上一轮的旧批准
→
05 · 程序
目录内执行
· 3046 条动作目录
· 参数固定 · 无 shell
· 四道核验后才执行
禁止：shell / 任意 SQL / 任意路径
→
06 · 探针
独立裁决
· 同一轮双探针 PASS
· PASS / FAIL / UNKNOWN
· 模型自述不算数
禁止：以模型自述判定恢复
只追加审计 · 按 rowid 回放 现场 → 证据 → 诊断 → 计划 → 审批 → 执行 → 复测；失败与拒答同样落库。
← 复测 FAIL：开新一轮，新计划、重新审批；旧批准不复用，同一动作成功过就不再执行。
UNKNOWN ≠ FAIL：缺失必需探针或观测未知时明确说“不知道”，不猜、不声称恢复。
